## 第一部分：地基——一次生成在模型内部的真实旅程

### 1.1 从你输入一句话到模型吐出一个字，发生了什么

```
"今天下雨了" 
  → 分词器切成 token（词片，如 [今天][下雨][了]）
  → 每个 token 查表变成一个向量（叫 embedding，维度 d，如 2048）
  → 这串向量进入 N 层"楼"（Qwen2.5-3B 是 36 层）
  → 每一层做两件事：注意力（看前文、收集信息）+ MLP（变换信息）
  → 最后一层的输出向量，乘一个大矩阵（unembedding），得到词表里
    每个 token 的分数（logits，15 万个分数）
  → softmax 把分数变成概率分布
  → 按分布抽一个 token（这里温度/top_p 介入）
  → 抽到的 token 拼回输入，重复整个过程 = 生成
```

【机制】关键事实：**模型一次只决定一个 token**。你看到的一段话，是几百次
「读全部上下文 → 算概率 → 抽签」的循环。我们所有的现象都发生在这个循环的某处。

### 1.2 残差流：模型内的"共享总线"

【机制】每一层的注意力/MLP 不替换信息，而是**往一条公共通道上累加**自己的输出。
这条通道叫残差流（residual stream）。可以想象：embedding 是起点站，每层是
一个往车上搬货的工人，最后一站把整车货拿去换算成 logits。

我们的"转向注入"就是**伪装成一个工人，往车上放一个我们自己造的包裹**：
`h' = h + α·v`（在第 L 层之后，每个 token 位置都加）。

代码：`src/model.py` 的 `HookManager._make_hook`。用 PyTorch 的
`register_forward_hook` 拦截第 L 层的输出，在捕获模式记录它（提取向量），
在注入模式修改它（转向）。

### 1.3 温度和 top_p 的确切数学

【机制】采样前，logits 除以温度 T：`p_i = softmax(logit_i / T)`。
- T=1：按原始分布抽签
- T→0：永远抽最高分（贪心）
- T→大：分布变平，低分 token 也有机会

top_p=0.95：把 token 按概率从高到低排序，只保留累计到 95% 的那批，其余
直接删掉再抽。

**注意一个关键区分**：温度改变的是"抽签方式"，不改变模型算出的分数本身。
模型分布（T=1）是模型的"意见"；温度是抽签时的"手抖程度"。这区分是
"潜伏/显影"双层测量的理论根据。

### 1.4 上下文学习（ICL）：权重不变，分布被撬动

【机制】把示例放进上下文，模型权重零变化，但注意力机制会让后续生成
强烈模仿上下文里的模式——这是 next-token 预测训练的直接副作用：
模型被训练成"看到什么模式就延续什么模式"。

为什么它经常打败显式指令（"不要加时间戳"却照样加）？三个机制叠加：
1. **证据 vs 否定**：N 条带时间戳的消息是 N 次正面示范；指令是一次
   否定约束。模型对否定句的处理天然弱——"不要想大象"问题。
2. **位置**：指令在 system（离生成点远），格式证据遍布每条历史（近处也有）。
3. **数量**：几十个格式样本 vs 一句禁令。

【实证】step5：生产格式 100% 泄漏；末位补一句禁令降到 8%
（位置效应）；删一半证据泄漏转移到剩余证据（打地鼠）。

## 第二部分：向量路线——做了什么、为什么失败、为什么对照成功

### 2.1 提取协议（确切操作）

代码：`src/extract.py`。以老渔夫的一句示例为例：

1. 构造对话：`[user: 请一字不差地复述下面这句话。] [assistant: 晓得伐，阿拉年轻时出海……]`
2. 前向一遍，**捕获第 L 层输出的最后一个 token 位置的向量**——
   这一点的残差流"汇总了整句话的信息"（【机制】末位置是全句的汇总点，
   CAA 等论文的标准做法）。
3. 12 句示例各得一向量；再对 6 句中性句子（"今天天气晴朗"）做同样的事，
   取平均作为基线。
4. `v_i = act(示例_i) − mean(act(中性句))`，再归一化到长度 1。
   直觉：减掉"普通句子的公共成分"，剩下的应该偏向"渔夫味"。
5. 平均版：`v_mean = normalize(mean(v_i))`。

### 2.2 余弦矩阵怎么读，聚簇说明什么

【实证】12 个单句向量两两余弦：均值 0.65，范围 0.30–0.92。
三个带"晓得伐"的句子互相 0.79–0.92。

解读：如果这些向量真的捕捉"抽象的渔夫风格"，它们应该高度一致（余弦 0.8+
且均匀）。实际的聚簇结构说明**向量主要编码的是表层特征**（哪句带哪个口头禅、
哪个内容锚），风格信息只是其中一小部分。这直接解释了 18862 论文的
"单示例方差"现象：**选哪个示例 = 选哪个特征簇**。

### 2.3 注入与层位扫描

【实证】step6：深度 0.4/0.5/0.6/0.7 四层 × 剂量 0.5/1.0，风格指标（口头禅）
全零。step7 加了三个修复变体（末8token池化 / 只在解码步注入 / 对照消元提取），
依旧全零。α=2.0 时出现退化（重复崩坏），说明向量**确实在影响生成**——
只是影响的方式不是"赋予风格"，而是"破坏连贯"。

### 2.4 为什么失败：三层机制

【解释】综合诊断（协议正交性 cos 0.15–0.51 是关键证据）：

1. **协议噪声主导方向**：提取模板（"请复述这句话"）、末 token 的句号语义、
   具体内容词——这些分量比风格分量大得多。换协议方向就大变（正交性），
   说明我们提取的"不是同一个东西"。
2. **习语风格不是一根方向**：说话风格 = 几百个小决策（选词、句长、语气词、
   节奏），这些决策发生在靠近 unembedding 的地方。中层的一根加法向量
   能推动"正式/随意"这种全局粗维度，推不动分散的细粒度分布。
3. **对照消元也没救回来**（step7 C 变体）：即使内容分量被配对减除消掉，
   剩下的风格残差仍然太弱/太散。

### 2.5 阳性对照为什么成功（同样重要）

【实证】step8：用同样的管线注入"正式度"方向（CAA 式正负指令差分），
负向（推向口语）把书面标记从 1.88 压到 0–0.5，四组配置一致。

【解释】正式度是**全局性的粗维度**——它对应残差流里真实存在的一根大方向
（大量训练信号塑造）。这证明：管线没坏，失败是"习语特异"的。
**特质可移、习语不可移**——这就是失效边界。

## 第三部分：上下文污染——金丝雀、哨兵、盆地

### 3.1 金丝雀协议的设计原理

设计目标：把"等泄漏自然发生"变成受控实验。三个要求（来自你的设计）：
1. **贴合人设**（鹦鹉对鸟族少女完全自然）→ 不会被合理性过滤掉
2. **话题不可达**（城市日常聊不到阁楼）→ 一旦出现必是泄漏，零误报
3. **far/near 话题对照** → "你喜欢什么小动物"是 near 话题，用于测自然可达性

【实证】far 话题下 none 条件 0% 显影（零误报），near 对照也 0%
（模型被直接问动物也不会说鹦鹉）——金丝雀合格。

### 3.2 概率哨兵的数学

代码：`scripts/step9b_canary_v2.py` 的 `gen_sentinel`。

生成时用 `output_logits=True` 拿到**每一步的原始 logits**（温度施加前）。
对每步计算：

```
P(金丝雀) = Σ_{i∈金丝雀token} exp(logit_i − logsumexp(logits))    ← T=1 潜伏质量
P_T(金丝雀) = Σ_{i} exp(logit_i/T − logsumexp(logits/T))          ← 采样实际面对的
```

金丝雀 token 集：扫描全部词表，取解码后含"阁/鹦/鹉"的所有 id
（v1 用 tokenize 取到的是字节碎片，是 bug，v2 修复）。

### 3.3 盆地进入：数据形态与机制

【实证】144 条 far 生成：潜伏峰值中位数 0.00008；8 条 >0.01，
其中 4 条 >0.6（鹦鹉一度是 60–99.99% 概率的下一词）。3 条实际显影，
其潜伏峰值恰好是全体前三（0.9993/0.9998/0.9999）。

【解释】双峰的来源：语义空间的"离散性"。生成轨迹要么停留在与鸟无关的
语义区域（此时鹦鹉 token 的概率被压在 1e-5 量级），要么因偶然的选词
走进"鸟相邻"状态（比如聊到"教/学/聪明/说话"），此时上下文里的金丝雀
（人设里的阁楼鹦鹉）被注意力激活，鹦鹉 token 的概率暴涨。**不存在中间态**
——这就是双峰。哨兵有效的原因：显影之前必经"概率暴涨"阶段，
我们读的正是这个量。

### 3.4 温度为什么只在边缘有效

【实证】进盆数按温度 2/3/2/1（平坦）；峰值 0.62 的那条在 T=0.7 逃逸；
峰值≈1 的三条全显影（与温度无关）。

【机制】数学上：温度作用于 softmax(logits/T)。
- 若金丝雀 logit 已是最高分（峰值≈1）：任何温度都抽它 → 温度无用
- 若金丝雀 logit 接近最高分（边缘）：低温时差距被放大（它输），高温时
  差距被抹平（它有机会赢）→ **温度只在边缘带起作用**
- 是否走进边缘带，取决于更早的选词轨迹 → 与当下温度关系弱

### 3.5 话题运河

【实证】8 次进盆里 5 次来自"学编程"话题。
【解释】"学编程"（难不难/值得投入）与"教鹦鹉说话"（训练/聪明/学会）
共享语义桥。话题起点坐落在金丝雀盆地的流域里。这提示：**"话题距离"
不是单一维度，要按语义桥来度量**——将来的实验可以按桥的强度分层。

### 3.6 回弹实验与"越聊越出戏"

【实证】step4 完整卡：元素提及率随轮次 6%→33%→44%，用户两次转话题压不住。
【解释】随对话累积，卡片里越来越多的表面变得"可关联"（每个新话题都可能
搭上某条语义桥）；用户转话题只压制了直接重复，压不住注意力对显著实体的
持续可用性。摘要人设版（不含背景细节）则平稳——**污染源是细节的丰度**。

## 第四部分：统一图景（星球模型）与诚实边界

| 概念 | 对应 | 状态 |
|---|---|---|
| 星球表面 | 下一词条件分布的语义空间 | 【解释】隐喻 |
| 盆地 | 上下文为显著内容安装的吸引子 | 【实证】双峰+峰值≈1 |
| 造盆地 | 上下文/角色卡写入显著内容 | 【实证】system 位最强 |
| 流域 | 话题起点的语义桥归属 | 【实证】话题运河 |
| 走路 | 逐步采样 | 【机制】 |
| 温度=盆缘高度 | softmax(logits/T) 的边缘效应 | 【实证】仅边缘带 |
| 哨兵=测距仪 | 逐步 P(金丝雀) | 【实证】排序完美 |
| 指令填盆 | "不要提起"类禁令 | 【实证】失败 |

**诚实边界**：星球模型是**解释框架**，不是被直接观测的实体。我们直接观测的
只有：输出文本、逐步 logits、层内激活。盆地/流域是对这些观测的最简解释，
它在Hopfield吸引子理论里有亲缘概念，但目前没有人（包括我们）画出过
"语义空间的等高线图"。**这是这个方向最深的一个开放问题。**
